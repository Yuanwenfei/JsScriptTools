# JsScriptTools 改造清单（对标 QLToolBox）

> 目标：把 JsScriptTools 从「9 个单文件 MCP 工具」升级为与 QLToolBox 同级别的
> **JScript 全生命周期工具箱**：读、写、静态检查、版本回滚、异常定位、导出导入、
> 回归测试。仅 MCP 工具形态（不实现属性驱动组件通道，用户已确认取消）。
>
> 对标文档：`../QLToolBox/README.md`（QLToolBox 工程，2026-09-30 实测版）。
> 本文所有「JS 特殊性」结论来自 `../README.md`（2026-09-25 实测版），非推测。
>
> **实施状态（2026-10-01）：16 项全部落地并验收。** 工具数 9 → **21**（12 个新增：`js_write`、`js_set_source`、
> `js_snapshot`、`js_diff`、`js_rollback`、`js_diag`、`js_lint`、`js_index`、`js_export`、`js_import`、`js_test`、`js_trace`；
> `rev` 无独立工具，贯穿 index/快照/写入回报/导出清单）。四阶段验收 A1–A6 / B1–B5 / C1–C4 / D1–D5 全绿，
> 记录见 `开发计划.md` §2.5、§3.5、§4.4、§4.5；实测坑表见 `../README.md` §9。实施中修正了三处原始设计：
> A3（JScript 写入时不编译 → 改为 lint 前置 + `verify=true` 真实校验）、B4（规则②不能做阻断项 → 降 warn）、
> 以及阶段四的 scaffold 事件名归一化。

| 维度 | 现状 | QLToolBox 目标态 |

| 组件通道（属性驱动） | 无 | **不实现**（已确认取消） |

| 诊断缓冲 | 无（错误散在各工具返回值里） | 进程内环形缓冲，`js_diag` 统一读 |

## 1. JS 域特殊性（改造时必须遵守的硬约束）

这些是从 `../README.md` 实测结论推出的设计约束，**每条都会改变 QLToolBox 功能的移植方式**：

| # | 约束 | 对改造的影响 |
|---|---|---|
| S1 | `ScriptContainer.Source` 只读；JScript 只能走「磁盘 `.js` + `Load()`」通道 | 写入闭环的"写入"和"回滚"步骤都基于磁盘回环实现；快照必须存源码文本（磁盘文件会被覆盖） |
| S2 | 写入已存在的 JScript 会使其 `LoadedFromDisk=True` | 报告与 lint 要标注"已磁盘化"状态；导出可直接引用该路径 |
| S3 | 编译失败的脚本会被**自动 Purge**（数据丢失） | **快照不是锦上添花，是防数据丢失的 P0**；写入闭环必须先快照再写入 |
| S4 | JScript 引擎非标准：无 `Math.*` 等 | lint 需要"不可用 API"规则；脚手架模板不能含 `Math.*` |
| S5 | 事件绑定 `<视觉名>_<事件名>` 命名约定，且**挂载只能走 UI** | index 应列出"事件函数 ↔ 场景视觉"对照表辅助人工挂载；工具不承诺自动挂载 |
| S6 | 工具程序集**在模型打开时注册**（2026-09-30 实测修正：保存后重开模型 + 刷新 IDE 工具表即可，无需退出 Emulate3D；**顺序必须是「推送→保存→重开」，先重开则磁盘仍是旧源码、引擎判定无更新→不换装**，兜底用完整重启） | 无组件保底通道（已取消），每次迭代必须按序「推送→保存→重开模型→刷新工具表」才可见，部署脚本与坑表（2.16）重要性上调 |
| S7 | 模型路径进程内不可得 | 导出必须显式 `dir=` 或走兜底目录（对齐 QLP 的 `我的文档\Emulate3D-QLP-Export` 做法） |
| S8 | `lib.Create` 产出的就是 JScript 容器 | 新建脚本不需要类型纠正逻辑（现状已修，保持） |

## 2. 改造清单（按优先级分层）

### P0 — 安全底座（先做这个，否则后续写入都有数据丢失风险）

| # | 项 | 内容 | 对标 | 验收标准 |
|---|---|---|---|---|
| 2.1 | **快照仓库** `JsSnapshotStore` | 进程内快照：写入前自动逐条建快照；支持 tagged 快照、按脚本名查询；只存源码文本（S1/S3） | `qlp_snapshot` | 故意写入语法错误 JS → 脚本被 Purge → `js_rollback(snapshot="last")` 完整恢复 |
| 2.2 | **写入闭环** `js_write` | 运行态门禁 → 目标解析（同名消歧，列候选）→ lint（error 阻断，`force` 可过）→ 自动快照 → 写入 → 编译 → 诊断 → 失败自动回滚 | `qlp_write` | 闭环单次耗时报告；语法错写入后自动回滚且诊断带行列；运行态返回 `REFUSED: the model is Running` |
| 2.3 | **诊断环形缓冲** `JsDiagBuffer` | 在赋源码/编译的源头捕获错误（ParseException 带 `line N, pos M`、编译错误、lint 结果、写入记录），进进程内环形缓冲 | `qlp_diag` | `js_diag(since="lastWrite")` 只返回本次写入的诊断；缓冲按程序集隔离的坑写进文档（QLP 坑 E） |
| 2.4 | **轻量写入** `js_set_source` | 无门禁/快照/lint 的直写（保留给已快照场景与脚本化批量操作） | `qlp_set_source` | 返回写入机制与回读 rev |
| 2.5 | **代码拆分** | 单文件拆为：内核 `JsScriptHelper.cs` + `JsTools.cs`(L0/L1) + `JsWrite.cs` + `JsDiag.cs` + `JsSnapshot.cs`；新文件名必须一次写对（QLP 警告：源文件无法删除） | QLToolBox 结构 | push-sources 一次编译通过；旧 9 工具行为不变（回归） |

### P1 — 全景与质量

| # | 项 | 内容 | 对标 | 验收标准 |
|---|---|---|---|---|
| 2.6 | **全模型清单** `js_index` | 每脚本：名称 / 类型 / 行数 / 长度 / rev / 磁盘化状态 / 磁盘路径 / 编译错误数 / `mountedOn`（若可反射）/ 事件函数列表（S5）；支持 `nameRegex`、`limit` | `qlp_index` | 与 `get_scripts` + 日志对账一致 |
| 2.7 | **rev 指纹** | FNV-1a 64 位，统一用于 index / 快照 / 导出清单 / 写入回报；定义为"回读源码"的指纹（写入后回读比对 rev，验证写入可靠） | QLToolBox §5 | 同一源码写入后读回 rev 一致 |
| 2.8 | **静态检查** `js_lint` | 起步 4 条 P0 规则（JS 版）：① 语法/编译错误（借编译器）；② 失效视觉引用（脚本里 `TypeLiteral`/视觉名在场景中不存在 → 列候选）；③ 事件函数名 ↔ 场景视觉对照（`X_OnReset` 但场景无 `X` → warn）；④ 不可用 API（`Math.*` 等，S4）。无法静态判定的一律降级 info/warn 并写明原因，**0 误报优先于覆盖** | `qlp_lint`（4 条 P0） | 对模型内真实脚本 0 误报；lint error 可阻断 `js_write` |
| 2.9 | **诊断读取** `js_diag` | `since`(lastCompile/lastWrite/秒数)、`kind`、`severityMin`、`limit` | `qlp_diag` | 结构化输出，与环形缓冲对账 |

| # | 项 | 内容 | 对标 | 验收标准 |
|---|---|---|---|---|

## 3. 关键设计决策（需求整理结论）

1. **快照先行**：S3（编译失败自动 Purge）使快照/回滚从 QLP 的 L3 提升为 P0。没有 2.1/2.2，任何批量操作（导入）都是裸奔。
2. **写入通道唯一**：所有写路径（write/rollback/import/set_source）收敛到内核一个 `WriteViaDiskLoad` 入口，策略链只服务 C# 工程且与 JScript 严格分流（README 缺陷 #2 的教训，保持现状守卫）。
3. **lint 规则克制**：JS 语法树解析能力有限，规则以"编译器结果 + 反射场景清单 + 文本模式"三路交叉，拿不准的一律 warn/info，沿用 QLP「0 误报优先」原则。
4. **无组件通道**：已确认取消属性驱动组件。S6 的代价因此完全暴露——每次改代码都要「推送→保存→重开模型→刷新工具表」才能验收（实测不需要退出软件），故 2.16 部署脚本与迭代循环文档的优先级实际高于其 P3 位置；且所有验收只能在 MCP 单侧完成。
5. **测试降级**：JS 无 `Demo3D.TestRunner` 等价物（待验证），`js_test` 只承诺脚手架与清单，运行交回人工——与 QLP「不做假精确」的边界哲学一致。
6. **不移植项**：属性驱动组件通道（用户取消）、`qlp_enable` 启用位语义（JS 无对应物）、widget 形参类型表（JS 类型标注体系不同，S4）。
