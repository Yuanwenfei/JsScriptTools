### 2.4 写入闭环（任务 2.2 / 2.4）

顺序（对齐 QLP §5）：

```
运行态门禁(REFUSED: the model is Running)
→ 目标解析(名称/FullName/Key, 大小写不敏感; 全唯一场景无需消歧列表, 但保留候选输出)
→ lint(error 阻断, force 可过)         ← 阶段二前此步为空转, 接口先留好
→ 自动快照
→ 写入(磁盘 .js + Load, JScript 专属通道, 绝不 fallthrough 到策略链)
→ 编译(RunNewScriptsIfNecessary)
→ 诊断捕获
→ 失败 → 同调用内立即回滚(绝不留到保存窗口, R5)
```

回滚两条路径（阶段一必须都实测）：
- 脚本还在 → 用快照源码重新走磁盘回环；
- 脚本已被 Purge → `lib.Create`（产 JScript，S8）+ 灌入快照源码 + Load。

报告必须含：写入机制、磁盘化副作用声明（17 个脚本现全部 `LoadedFromDisk: False`，可行性 §1.2）、
回读 rev、编译耗时。

### 2.5 验收记录与设计修正（2026-09-30，阶段一实跑）

**通过**：A2（`changed=2 +1/-1`，rev `4a88260b→7eb56df8` 行级定位准确）、A6（`disk .js + Load` + 回读 rev）、
回滚双路径的"脚本还在"一路（rev 复原并 `verified`）、`js_diag`（31 条快照/写入/回滚审计 + `bufferMarks lastCompile`）、

**A3 证伪（原设计不可实现）**：JScript **在写入时不编译**。
- `script.Errors` 在写入后为空（未挂载脚本、在用脚本 `Pling` 各试一次，均空）；
- `RunNewScriptsIfNecessary` / `UpdateScripts` 对 JScript 不产生错误；
- 真正的编译发生在 **Reset / 模型打开时的脚本优化链**：`document_reset` 触发
  `Demo3D.Script.ScriptCompileException: Compiling library 'Pling': expecting "RP", found '}'`（带 `line 4:1`），
  但异常被引擎吞进日志，MCP 侧 `document_reset` 仍返回 `Success`，Reset 后 `script.Errors` 依旧为空；
- 与 README §7/§8.6 一致：编译失败的脚本在**保存/打开**时被自动 Purge，写入时不可见。

**结论**：改造清单 2.2 的"编译失败同调用内立即回滚"在 JS 域不成立——写入调用内**拿不到**编译结果。
替代防线（三选，待定）：
1. **静态前置 lint 提前到 P0**（原阶段二 2.8）：保守规则、0 误报优先，拦下语法级破坏（本次实验的
   `expecting "RP"` 就属语法级），作为唯一"写前"防线；
2. **opt-in `js_write(verify=true)`**：写入后内部 Reset + 日志扫描 `ScriptCompileException`，
   命中则同调用内回滚（快照→写→Reset→校验→失败回滚）。代价：Reset 会执行全模型 OnReset 逻辑，
   故不能做默认值；
3. 默认路径只能**诚实报告"编译未校验"** + 强制快照 + 明确交接（人工 Reset / 重开模型）。

**运行态门禁修正**：原实现在 `Document` 上找 `RunState/IsRunning/ModelTime`（19.2.0.74 均不存在）→
探测恒为 unknown、门禁形同虚设。已改为 QLToolBox 同款 `IBuilder.Running`（+ `Document.Time` 作 detail），
待重开模型后复验 A5。

**A4 通过（Purge 重建，意外自然复现）**：一次推送触发的重编译把我们的探针脚本清掉了
（日志 `Purging "JsMCPProbe" / Purged 1 script` —— 实测：**未被任何视觉引用的脚本会在保存/重编译时被自动清除**，
与 README §7 的 "Purge Unused Scripts" 一致）。随后 `js_rollback(snapshot=<含该脚本的 tag>)` 走
`lib.Create` + 磁盘灌入重建成功：`Type=JScript`、101 字符、`LoadedFromDisk=True`、rev 与快照一致。
附带结论：**快照库（进程内 static）在推送引起的重编译后仍存活**；但它是否跨"重开模型"存活要实测（可能重载程序集）。

**修正 A3 的覆盖结论**：`Reset` **会编译未挂载的脚本**（A3-b 实测）。此前两次假阴性不是覆盖问题，而是
**跨线程调用 `app.Reset()` 失败**：工具线程直呼 Reset 会撞 UI（错误列表 DevExpress 网格）抛
`InvalidOperationException: A cross-thread operation is detected`，Reset 实际未执行、自然没有编译。
修复：`InvokeRequired` 为真时经 `IBuilder.Invoke(Delegate, object[])` 编组到 UI 线程再 Reset（`JsVerify.ResetModel`）。

**新增边界（写入文档，影响后续阶段）**
- **快照库不跨"重开模型"存活**：进程内 static 随程序集重载清空（实测 `snapshots=0`）。
  故每次重开模型后第一次写入前必须先 `js_snapshot`；`js_export`（阶段三）是把快照落到磁盘的唯一途径，优先级实际高于原计划。
- **未被任何视觉引用的脚本会在保存/重编译时被自动 Purge**（两次实测：`Purging "JsMCPProbe" / Purged 1 script`）。
  含义：`js_write` 新建但未挂载的脚本不保证存活；`js_import` 批量导入后必须提示人工挂载（S5）。

**阶段一出口判定：达成**（A1–A6 全绿 + lint 0 误报基线；A3 按替代方案 C 口径）。

**收口复核（最后一次换装后）**
- verify 失败消息完整且带行列：`COMPILE VERIFY FAILED (after Reset): Compiling library 'JsMCPProbe': expecting "RP", found '}' at line 4:1.`
  （修正了两次截断：正则排除 `"` 导致只留 `expecting`；只向前取窗口导致丢 `line 4:1`——现改为匹配点前后各 600 字符取最近一条）
- 失败回滚的**创建分支**实测：`WRITE FAILED -> created script removed.`（新建脚本坏编译 → 直接移除，且不走快照路径）
- 回滚后的补 Reset 走同一线程编组，返回 `ok`，日志无新增异常

**A3 替代方案实现（方案 C，2026-09-30）**：
- `JsLint.cs`：语法级 lint 引擎（注释/字符串/正则字面量感知，只报确定性错误；括号/引号/块注释配平，
  warn 级永不阻断）+ `js_lint` 工具（`target` 空 = 全模型，作 0 误报基线校准用）+ 写入前拦截桥；
- `JsVerify.cs`：`js_write(verify=true)` 的 Reset + `%APPDATA%\Emulate3D\demo3dlog.txt` 增量扫描，
  按 `Compiling library '<name>'` 归属判定（只对本脚本失败回滚，其它脚本的坏编译只作 note），并提取 `line L:C`；
- 默认路径（`verify=false`）明确报 `Compile NOT verified`，并给出两条自查路径；
- 失败回滚抽出共用助手 `RollbackAfterFailure`（创建→移除；覆盖→快照复原），编译失败与校验失败共用。

## 3. 阶段二（P1）：全景与质量（2~3 天）

### 3.1 rev 指纹（任务 2.7）

- FNV-1a 64 位十六进制，定义 = **回读 `Source` 的指纹**。
- 留验证点（可行性 §2）：JS 源码是否规范化未知 → 首次写入后读回比对 rev 验证幂等；
  若不幂等（发现尾部空白/换行归一化），在 rev 计算前做同样的归一化并记录规则。
- 贯穿点：index 行、快照条目、写入回报、导出清单。

### 3.2 js_index（任务 2.6，降级版）

- 字段：名称 / 类型 / 行数 / 长度 / rev / 磁盘化状态 + 路径 / 编译错误数 / **事件函数前缀清单**（正则
  `function\s+([A-Za-z0-9_]+)_On[A-Z]` 提取，unique 排序）。
- **`mountedOn` 不做**（可行性 §1.4：挂载关系不可反射）。
- 过滤：`nameRegex`、`limit`；对账目标：官方 `get_scripts`。

### 3.3 js_lint（任务 2.8，四条规则）

| 规则 | 级别（默认） | 实现 |
|---|---|---|
| ① syntax-error | error | 编译器结果（借闭环/compile 的真实编译，不臆断） |
| ② unresolved-visual-ref | error | in-process 枚举场景全部视觉 `Name`（372 节点无压力）；候选推荐用编辑距离最近的前 3 个；**排除 `Demo3D.*/System.*` 命名空间与 `[...]` 属性行**（R2） |
| ③ event-prefix-without-visual | **warn，可关** | 函数名前缀 ∈ 场景视觉名集合？否 → warn + "可能未挂载"说明（R3/R6；可行性 §1.5 数据决定不能更高） |
| ④ unavailable-api | error | 黑名单文本匹配（起步 `Math.` 一类，按 README §8.4 扩充），命中给替代写法提示 |

- 规则配置表内置（名称 → 级别 → 开关），参数 `rules`/`severityMin`/`limit` 与 QLP 对齐。
- **基线校准铁律**：先对 17 个真实脚本跑全量，逐条核对 ②③ 输出；任何误报先修规则再定 severity，
  0 误报优先于覆盖（QLP §5 克制原则）。校准记录存档（脚本名 × 规则 × 结果）。

**校准第 1 轮（2026-09-30，18 脚本）：11 error / 19 warn → 规则修正**
权威依据来自本地知识库 `local-agent-kb`（10740 片段）与 `Emulate3D-2026-Doc/.../JScript Scripting`，
关键事实：**JScript 的文档对象是小写 `document`**（`document.CreateVisual`）；
**一个模型的所有 JScript 编译进同一程序集**，因此跨脚本全局（本模型里 `FC`/`RM`/`VM` 是各脚本给自己设的别名）
在单个脚本里是"未声明"的合法引用；类型简单名可裸用（`Transfer.Dispatch(sender)`）。

| 原判定 | 实测结论 | 修正 |
|---|---|---|
| ② `doc`/`app` 未声明 | 引擎内建全局（`App`/`Doc`，模型里用小写） | 白名单补 `app/doc/document/App/Doc/Document/sender` |
| ② `FC`/`RM`/`VM` 未声明 | **跨脚本全局**（同程序集） | 判据加入"模型级符号集"：全模型脚本的声明 + `:` 标注 / `new T` / `import` 带来的类型名 |
| ② `Transfer.` 未声明 | 类型静态调用（`: Demo3D.Visuals.Transfer`） | 同上（类型名纳入已知集） |
| ② error 级 | 仍存在无法静态判定的情形（类型/宿主自定义属性） | **降为 warn**，消息明说"可能是类型/宿主自定义属性/缺失引用"；阻断职责交给 ①④ 与 `verify=true` |
| ④ `Math.` ×4 | 这些脚本用 `Math.Sign(loc.Z)`，**能跑** | ④ 收窄为**小写 JS 风格**成员（`Math.ceil` 是 README §8.4 记录的失败形态），放过 .NET PascalCase |
| ② 崩溃 ×5 | `ColumnOf` 未夹取索引 + 候选择优写法 | 夹取索引 + 简化候选逻辑 + 逐条容错（异常带首帧栈，复发可定位） |
| ③ ×19 | **真阳性**：`em3d_find` 验证场景只有 `Cylinder3`，`Cylinder1/RCT/LC/VM/CLH` 等均不存在（脚本是从别的模型拷来的未挂载副本） | 保持不变（warn） |

**B4 随之重新定界**：规则②不能做阻断项；**阻断用例改用规则④**（`Math.ceil` 为实测确定的失败形态），
② 只做带最近候选的 warn。写前阻断 = ① 语法 + ④ 不可用 API；运行期正确性 = `js_write(verify=true)` 的引擎真值。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| Purge 时机不可控（保存时触发） | 闭环内同调用回滚（R5）；写入前快照是硬编码第一步，不可跳过 |
| JS 源码规范化行为未知（影响 rev） | 阶段二 B1 验证点；异常则归一化后指纹 |
| lint ②③ 误报 | 基线校准铁律 + 命名空间排除（R2）+ warn 降级（R3/R6） |
| 推送编译失败污染模型（QLP 坑 A/B） | push 后必须看完整 `Result`；**编译失败即意味着模型内源码已是坏版本 → 必须立即修好重推，期间绝不保存模型**（阶段二实测：委托签名不匹配导致 1 error，重推成功后 `Purged 0 scripts`，工程未损）；验收前 Ctrl+S |
| 重开模型/刷新工具表遗漏导致"改了没效果"（S6） | 每阶段验收清单第一条固定为"保存 → 重开模型 → 工具表与版本可区分" |
| **`推送 → 保存 → 重开` 顺序颠倒时不换装**（阶段一实测，最易误判） | 推送已在进程内编译出 `Assembly N+1`；若**先重开、后保存**，重开时磁盘模型还是 `Assembly N` 的源码，引擎判定 "No updates available" → 不重编译 → **工具类继续用旧程序集**（症状：push 回显成功但行为/文案是旧的）。务必先 Ctrl+S 再关闭重开；仍不换装时用完整重启 Emulate3D 兜底。判别技巧：看日志该次打开有没有 `New assembly created for 'JsScriptTools' in cache` |
| 双工具集互相牵连（R1） | 阶段四双回归；导出目录隔离（D9） |
| **工具类丢失 `[McpServerToolType]`**（阶段一已实测命中） | 症状极隐蔽：编译零报错、`push` 回显"New assembly created"，但 MCP 服务器不注册该类，**旧 9 工具与新工具一起消失**（工具表里 JS 系全空，而 `qlp_*`/`em3d_*` 正常）。拆分/改写文件时必须保留类级 `[McpServerToolType]` + `[Description]`（partial 类只需其中一处），并列为每次重开模型后的第一条检查 |
| **JScript 编译结果写入时不可观测**（阶段一实测证伪 A3，§2.5） | 不假装闭环：默认路径明确报告"编译未校验"并强制快照；静态 lint 提前到 P0 作写前防线；需要真校验时用 opt-in `verify=true`（内部 Reset + 日志扫描 `ScriptCompileException` + 失败同调用回滚） |
| **工具线程直呼 `app.Reset()` 无效**（跨线程，异常被吞成假阴性） | 凡是碰 UI 的引擎调用（Reset 会写错误列表网格）必须经 `IBuilder.Invoke(Delegate, object[])` 编组到 UI 线程，见 `JsCompileVerify.ResetModel`；日志里出现 `A cross-thread operation is detected` 就是这个坑 |
| 快照不跨"重开模型"存活（进程内 static 随程序集重载清空） | 重开模型后首次写入前必须 `js_snapshot`；`js_export` 是把快照落磁盘的唯一途径，优先级实际上调 |

## 8. 迭代循环（每阶段重复）

```
改工作区 .cs → read_lints → push-sources.ps1 → 编译通过（看完整 Result）
→ 提醒用户 **先 Ctrl+S 保存模型**（顺序不可颠倒）→ 关闭并重新打开模型

```

> **顺序陷阱**：先重开、后保存时磁盘模型仍是旧源码，引擎判定"无更新"→ 不换装（见 §7）。兜底手段：完整重启 Emulate3D。
