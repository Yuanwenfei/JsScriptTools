### 1.2 JScript 容器状态（抽样 inspect ×4 + 清单全量特征）

- 全部 17 个：`SourceSetter: False`、`IsNative: False`、`HasDllSource: False`、
  `NativeKeys` 为空、**`LoadedFromDisk: False`**、`IncludeInCompilation: True`。
- 即：全部脚本目前**只活在模型文件里，未磁盘化** —— 首次写入即触发 S2 副作用
  （`LoadedFromDisk → True`），写入闭环报告必须显式声明这一点。
- 当前无编译错误（日志干净，仅框架正常编译记录）。

### 1.3 场景规模与命名

- 节点 372 个（`em3d_model_state`）；同名视觉存在（如 Cylinder5 ×N、Cylinder8 ×N），
  但**脚本名 24 个全唯一** —— QLP 那种"41 个 Box1 消歧"问题在脚本域不存在，
  `js_write`/`js_get` 的目标解析可简化为"名称/FullName/Key 三级 + 大小写不敏感"（现状已有）。

### 1.4 挂载状态反射（js_index 的 `mountedOn` 探测，结果：**不可行**）

| 探针 | 结果 |
|---|---|
| `get_property(Cylinder3, ScriptName)` | `Property 'ScriptName' not found` |
| `get_property(Cylinder1, ScriptName)` | `Visual not found`（场景无 Cylinder1） |
| `em3d_find(hasProp=ScriptName)` | **0 命中** |
| `em3d_find(hasProp=Scripts)` | **0 命中** |

- 场景视觉 `Group1.HelpButton1.Cylinder3` 真实存在，与 HelpButton 脚本的
  `Cylinder3_OnClick` 前缀吻合，但其上反射不到任何脚本挂载属性。
- 结论：**挂载关系经 MCP/反射均不可得**（与 README §8.2 一致：挂载只能走 UI）。
  `js_index` 的 `mountedOn` 字段取消，降级为"事件函数前缀清单"。

### 1.5 事件函数前缀 ↔ 场景视觉对照（js_lint 规则③的校准数据，结果：**数据不利**）

`em3d_find` 实测：场景存在 Cylinder2/3/5/7/8，**不存在 Cylinder1/Vehicle/SRM/LC/Pling**。

- 17 个 JS 脚本里大量前缀（`Vehicle_*`、`SRM`、`LC_*`、`Cylinder1_*`）无同名视觉 ——
  这些多为 QS2010 系列**模板/库脚本**，本场景未挂载或挂载在别名下。
- 若规则③按"前缀必须匹配场景视觉"做 error 级检查，将大面积误报；
  若做 warn 级且写明"脚本可能未挂载"，则信息价值有限（用户大多知道）。
- 另注意 `LC_OnReset` 说明**前缀不一定是视觉全名缩写约定，就是字面前缀**，
  规则只能做"前缀是否等于任一视觉名"的纯文本匹配。

### 1.6 源码语法实测（抽样读源 ×3）

JS 脚本语法远比 README §8.4 记录的基础子集丰富，lint 规则设计必须考虑：

- 属性块：`[Optimize(true/false)]`、`[Message("OnProcessComplete")]`、
  **`[QuickLogic("records from {fileName}")]`**（FlowControl —— JScript 与 QuickLogic 交叉存在）；
- `import System.* / Demo3D.Script.Sequences`；类型标注走完整命名空间
  （`Demo3D.Visuals.StraightRollerConveyor`）—— **不得**被规则②误判为视觉引用；
- 成员链 `sender.Sphere.Visible`、`sender.Parent.TransferStateEnabled` —— 失效成员
  静态判定不可行（类型来自 sender 运行时绑定），保持 QLP 的克制原则。

### 1.7 Purge 机制实证（快照 P0 必要性的再次确认）

今日日志（22:08–22:09）：`Script "QLToolBox" (guid) purged while saving "QuickLogicTools"`、
`Script "Em3dToolScript" … purged` —— **Purge 在模型保存时真实发生**。
对 JS 写入闭环的含义：写入语法错 → 不立即丢，但**下次保存即丢**，且磁盘化副作用
（S2）使"从磁盘找回"这条路也不可靠。快照必须是写入前的第一个动作。

## 3. 新发现的风险与注意点

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | 本模型即 QLToolBox 开发模型，两工具集共存 | 命名冲突：无（脚本名全唯一）；但 push 编译失败会互相牵连 | 回归验收时两工具集各跑一遍 |
| R2 | JScript 内含 `[QuickLogic(...)]` 属性（FlowControl） | lint 文本规则可能误伤 QLP 相关块 | 规则②排除 `Demo3D.*`/`System.*` 命名空间与 `[...]` 属性行 |
| R3 | 事件前缀 ≠ 视觉全名（`LC_*`） | 规则③无法做语义校验 | 只做字面前缀匹配；warn 级 |
| R4 | 视觉嵌套深（`Group1.HelpButton1.Cylinder3`，D=3~9） | 前缀匹配用 Name 而非 path | 枚举时取 `Name` 集合即可 |
| R5 | Purge 在保存时发生（日志实证） | 语法错写入后到下次保存前窗口期有补救机会 | 闭环内"编译失败立即回滚"必须在同一次调用内完成，不留窗口 |
| R6 | 大量未挂载模板脚本 | lint 基线若按"挂载脚本"假设会误报 | 基线校准用全部 17 个脚本，不只挂载的 |

## 4. 结论

1. **清单整体可行**，16 项中 12 项全绿、4 项需降级或调权，无阻断项。
2. 两项降级确认：`js_index` 去掉 `mountedOn`（§1.4）；`js_trace` 改为最佳努力 + 诚实边界（§1 探测不到异常格式）。
3. 一项调权：`js_lint` 规则③降为 warn 默认可关，且**阶段二开工前必须先用 17 个真实脚本做 0 误报基线校准**（§1.5 数据已显示该规则天然高误报）。
4. 写入闭环两个实测确认的新要求：报告声明"磁盘化"副作用（17 个脚本全部未磁盘化）；编译失败立即回滚、不留到保存窗口（R5）。
5. 建议按 `改造清单.md` §4 阶段顺序推进，阶段一验收增加一条："Purge 后重建脚本"路径实测。
